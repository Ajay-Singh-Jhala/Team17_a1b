# Design notes and wireframes

## Users and jobs to be done

- **Customer:** inspect wallet balance, place an order, understand why a checkout fails, and see the audit evidence generated by a wallet trigger.
- **Restaurant manager / evaluator:** browse orders, move an order through its lifecycle, compare restaurant revenue, refresh the materialized view, find nearby active drivers, and inspect reviews/menu catalog documents.
- **Teaching assistant:** verify all four workflows use the inherited database logic, with meaningful loading, empty, and error states.

## Visual system

- Palette: deep forest (`#142c26`), action green (`#176b52`), lime accent (`#c9f36a`), pale mint (`#e5f4ed`), and soft neutral canvas (`#f4f7f5`).
- Typography: Manrope for headings and DM Sans for body/UI (system fallback remains available).
- Reusable elements: persistent sidebar, page header, panels, status pills, buttons, paginated table, form controls, empty/loading states, metric cards, and small data visualizations.
- Responsive behavior: sidebar navigation becomes horizontally scrollable on narrow screens; two-column panels stack vertically; tables scroll horizontally rather than shrinking their content.
